1. Middleware-Prioritized Zero-Leak Multi-Tenant Isolation

In poorly ordered multi-tenant frameworks, route model binding resolves database records before tenant context is established—creating critical cross-tenant IDOR vulnerabilities. Benteng Siber explicitly locks kernel middleware execution order:

Authenticate → IdentifyTenant → EnsureTenantActive → SubstituteBindings
  • Cross-Tenant Route Binding Blocked: Every bound model (Task, Customer, ODP, Material, User) is resolved strictly inside the active authenticated tenant scope.
  • Child Table Isolation: All secondary records—ProofOfWork, ProgressUpdate, TaskMaterial, and TechnicianLocation—are explicitly scoped to the active tenant on every analytics and dashboard query.
  • Root Master Isolation: Access to /master-admin is restricted solely to the Root Platform Tenant (tenant_id === 1). Secondary tenant Super Admins receive a deterministic HTTP 403 Forbidden.

2. AES-256-CBC At-Rest Credential Encryption

ISPs store high-privilege integration secrets inside their tenant configuration: MikroTik RouterOS API passwords, OLT/GenieACS credentials, Midtrans Server Keys, and WhatsApp Gateway tokens.

Benteng Siber encrypts all tenant network_settings and settings columns at rest in MySQL using AES-256-CBC with HMAC-SHA256 integrity MAC via a custom EncryptedArrayOrLegacyJson cast. Even if a raw database dump is exposed, ISP router and payment keys remain cryptographically unreadable.

  • Hidden Serialization: Encrypted secret columns are excluded from JSON API responses by default ($hidden).
  • Per-Tenant Config Partitioning: Runtime settings files are isolated per tenant (settings_tenant_{id}.json) so changes in one ISP can never bleed into another.

3. Outbound SSRF Guardrails & Signed Webhook Integrity

Because FiberOps communicates with external MikroTik routers, OLT controllers, and custom webhook endpoints, strict outbound validation is mandatory:

  • SSRF Protection: Outbound drivers block loopback interfaces (127.0.0.1, ::1), link-local addresses, and cloud instance metadata endpoints (169.254.169.254) to prevent internal network pivoting.
  • Payment Webhook Verification: Midtrans QRIS webhooks enforce rate limiting, cryptographic signature checks, and exact gross_amount matching against the database invoice before triggering MikroTik un-isolation.
  • Brute-Force & Replay Defense: Login routes enforce 5 requests/minute throttling; mobile mutation endpoints require idempotency keys to stop replay or duplicate stock deductions.

4. Immutable SHA-256 Hash-Chained Platform Audit Ledger

Every privileged platform action performed inside the Root Master Console—such as suspending a tenant, switching a subscription tier, extending trial limits, or logging an Enterprise activation inquiry—is permanently recorded in platform_audit_logs.

Audit Field Security Guarantee
prev_hash & entry_hash Each log entry hashes the previous entry's SHA-256 digest plus current actor, action, tenant, payload, IP, and timestamp—forming a tamper-evident blockchain-style ledger.
Append-Only Enforcement Application-layer model hooks throw an immediate exception on any UPDATE or DELETE attempt against existing audit records.
Live Chain Verification Master Console displays real-time chain integrity verification (VERIFIED vs. BROKEN) across all governance entries.

5. Enterprise Abuse Prevention & Verification Guardrails

To protect multi-tenant cluster capacity from automated abuse, public self-registration at /register-isp automatically provisions instant 14-day trials only for Starter ($249/mo) and Growth Regional ($990/mo) tiers.

The unlimited Enterprise Carrier ($4,950/mo) tier is guarded server-side and routes directly through our Verified Enterprise Activation workflow—recording each request into the immutable platform audit trail for rapid architect onboarding.

6. OWASP Edge Headers & RFC 9116 Vulnerability Disclosure

All Benteng Siber web domains enforce strict HTTP response hardening at the server edge:

  • Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
  • X-Content-Type-Options: nosniff & X-Frame-Options: SAMEORIGIN
  • Referrer-Policy: strict-origin-when-cross-origin & strict Permissions-Policy
  • Verified RFC 9116 disclosure policy published at /.well-known/security.txt
