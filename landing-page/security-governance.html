2. Middleware-Prioritized Zero-Leak Multi-Tenant Isolation

To eliminate subtle Route Model Binding IDOR vulnerabilities where models hydrate before tenant resolution, Benteng Siber locks the HTTP Kernel middleware priority order:

Authenticate → IdentifyTenant → EnsureTenantActive → SubstituteBindings
  • Child Table Scoping: All secondary records—ProofOfWork, ProgressUpdate, TaskMaterial, and TechnicianLocation—are explicitly tenant-filtered on every query and analytics endpoint.
  • Per-Tenant Config Partitioning: Tenant settings are isolated into dedicated files (settings_tenant_{id}.json) preventing cross-ISP config drift.

3. AES-256-CBC At-Rest Credential Encryption

ISPs entrust Benteng Siber with MikroTik RouterOS API passwords, OLT/GenieACS credentials, Midtrans Server Keys, and WhatsApp Gateway tokens. Every sensitive column in tenants.network_settings and tenants.settings is transparently encrypted at rest in MySQL using AES-256-CBC + HMAC-SHA256 and excluded from serialized API payloads.
